# 制作工作流

## 1. 明确任务

记录主题、受众、中心问题、一个核心结论、模式、输出语言、总时长、样片时长（如适用）、尺寸、fps、音频选择、可用参考。在项目说明或 `brief.md` 中保存，便于后续修改沿用。常规缺项使用 skill 默认值；只有答案明显改变交付物时才提问。

扩展视频时读取实际源码、时间线、字体、配色、素材和已认可的开头。保留有效内容。如果只有成片，区分直接复用片段和重建源码；没有工程时不能承诺像素级一致。

完成条件：交付物与观众应该学会的内容明确。

## 2. 核实讲解内容

对会变化的技术事实、准确引文、科学发现、日期、限制与产品能力，查询最新一手来源。优先用户提供的材料和官方文档。无法浏览时标记未核实内容，不能编造引用。数值比较需要依据，虚构数据必须注明“示意”。

在 `sources.md` 中维护简洁事实表：主张、直接 URL 或材料位置、访问日期、适用配置/版本、画面含义。区分事实、简化和示意数据。例如重试箭头必须有明确触发条件；托管服务边界不能暗示它替用户编写业务逻辑。

缩小场景范围以保证准确：说明协议、部署模式、成功/失败行为，以及相关的一致性或重试语义。包含一个有价值的限制。非技术题材同样核对证据、因果、时间顺序和不确定性；没有依据时不能把相关性画成因果关系。

完成条件：重要主张有证据或显式的不确定性标记；例子的数据前后一致。

## 3. 规划时间和画面含义

分镜包含：起止时间、学习目标、可见对象及状态、动作、准确字幕、音频提示、对应事实表条目。场景覆盖要求的总时长，没有意外空档或重叠；明确设计的转场可以在画面上重叠。

贯穿同一个例子：提出问题，展示正常机制，暴露失败或边界，再回到结论。两分钟通常适合 6–8 个有意义的节点；三分钟可加入更深入的例子与失败场景。这只是参考，不是硬性段落数。

扩展靠增加解释：展示此前隐藏的步骤、比较两种条件、跟踪失败与恢复，或增加具体算例。仍然合适时保留已认可的开头。不要靠长时间停顿、重复字幕或降低播放速度凑时长。

用共享时间线（如 `timeline.json`）组织场景、字幕、音频事件和审阅时间点。明确时间单位和 fps。时长 D、帧率 F 对应 N = round(D × F) 帧，采样 t = n/F，n = 0…N−1。时间线终点 D 不是额外一帧。在任务说明中约定时长误差，默认 ±1 秒。

按所选语言编写自然可读的字幕；英文和中文不能按固定字词比例翻译。初次排版可使用最多两行短字幕、5% 安全边距，再按实际输出尺寸检查。少量文字可能需要 2 秒，密集解释要延长或删减。这些只是起点，不能代替可读性检查。

完成条件：总时长正确；每个动效都表达可识别的状态变化、关系或因果。

## 4. 选择一个渲染方案

合适时复用现有引擎；否则选择一个：

- React 项目：Remotion 及其按帧驱动的动画工具。
- HTML/SVG/Canvas 项目：HyperFrames，或 HTML + Playwright + ffmpeg，并提供确定性的 `seek(t)` 入口。

调用前阅读已安装引擎的当前文档，不要编造通用 CLI。添加依赖时使用项目环境和 lockfile。复用有使用权的本地字体/素材，记录来源与许可。本 skill 本身不需要云账号或 API key。

HTML 渲染中，`seek(t)` 必须根据 t 决定完整画面，包括字幕、路径、粒子和转场。避免墙上时钟定时器、实时网络数据、未固定种子的随机数，以及依赖前一帧的动画状态。捕获前等待字体与素材就绪。按帧引擎使用原生 API 达到同样的确定性要求。

对象身份和颜色保持一致；区分数据流与控制/配置连线；不是物理机器的概念分组必须标明。不要把请求画成穿过 DNS 查询或授权策略服务器来处理业务。

完成条件：代表性画面能渲染；重复定位同一 t 得到相同结果；记录复现命令。

## 5. 预览、检查、渲染

制作用户要求的样片或内部短草稿并检查。内部草稿不自动形成新的审批关卡。如果用户要求先认可样片，交付可审阅样片后等待；否则修正并继续。

抽取场景起点、中点、终点与转场边界，必要时包括前后一帧。联系表（contact sheet）标注时间戳。检查裁切、缺字、对比度、遮挡、字幕、箭头方向和事实含义。抽样帧不是完整播放验证。

通过视频播放或可用的等效方式检查阅读时间、节奏、连续性、音画同步与音频削波/杂音。使用生成或有适当许可的音乐，不继承案例的特定歌曲和第 17 秒节点。只有用户要求时才加旁白，并按真实语音时长调整时间线。

按模式渲染最终产物。用 ffprobe 或等效工具检查时长、尺寸、fps、音视频流、编码兼容性与文件可读性。支持时优先可广泛播放的 MP4：H.264/yuv420p，有音频时使用 AAC。记录实际参数，不能只抄预期设置。

完成条件：产物存在，媒体参数符合任务，视觉与时间检查有记录。无法完整播放、试听或渲染时，明确标记对应检查未验证。

## 6. 交付可复现工程

沿用现有命名；新项目可以使用：

```text
brief.md                 # 模式、语言、假设、输出约定
storyboard.md            # 时间、动作、准确字幕
sources.md               # 事实与素材来源
timeline.json            # 渲染与检查共用的时间来源
src/                     # 可编辑场景及所需本地素材
output/preview.mp4       # preview 模式
output/final.mp4         # full/extend 模式
output/contact-sheet.png
qa.md                    # 实际检查、限制、修正
README.md                # 依赖、准确的渲染/预览命令
```

Prompt-only 模式把相关约定写入 prompt，不生成这些渲染产物。包括一手来源链接，并要求接收方重新核实会变化的事实。

说明创建了什么、路径、复现方法和剩余限制。区分“已规划”“已渲染”“已检查抽帧”“已播放/试听”。只有交付了所要求产物，以及工具条件允许的实际检查后，才能说视频已经完成。
