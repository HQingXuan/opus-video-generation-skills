# 评估

[English](README.md)

## 离线打包检查

在仓库根目录运行 `python3 scripts/validate.py`。检查本地链接、可独立安装的 skill 引用、中英文文件配对、八个案例时间线（含连续性与总时长），以及 [cases.json](cases.json) 的模式覆盖。

这些验证打包，不验证翻译语义或模型行为。人工对照双语路由、默认值、覆盖规则和完成标准；制作前重新核对案例的一手来源。

## 用 Opus 检查行为

在临时测试项目中安装 skill。对 [cases.json](cases.json) 中每个案例使用新对话，并提供指定上下文/文件。记录实际模型版本、日期、可用工具、prompt、输出文件，以及各检查项的通过/失败/未验证状态。模型由评估者配置，skill 不选择模型。

规划和 prompt-only 案例可以不渲染。渲染案例需要本地引擎、相应浏览器与编码器。测试完整行为时原样执行请求；把 full 模式改成只做计划，可以测试路由，但不能算通过渲染验收。

扩展场景先创建真实样片工程，在 brief 中保存 `language: zh`，再提供该目录。缺少渲染器场景要实际实施所述限制。无关请求场景只让 skill 可被发现，不显式调用它。

十二个案例覆盖：默认英文、中文触发、显式覆盖、保留项目语言、冲突选择词、仅写 prompt、样片停止、扩展、非 AWS 主题、工具不可用、参考缺失和无关请求。事实或输出语言检查失败时，同步修正适用的双语版本，再重跑受影响案例。

真实成片要检查关键/转场帧、重复 seek 的确定性、媒体参数，并在条件允许时播放/试听。记录实际执行的检查。只有 contact sheet 不能算通过播放/音频检查。

## 当前证据

仓库提供结构验证和行为测试规格，没有 Opus 评估记录或新渲染样片。不能因为 JSON 解析成功就把行为案例标为通过。历史 SQS 样片效果来自用户反馈，见[来源记录](../docs/history.zh.md)。
